# Восстановление локального запуска без изменения схемы

Этот режим предназначен только для уже подготовленного локального ORION Clinic.
Он не обновляет схему, не создаёт пользователей и не заменяет проверку совместимости
текущего кода с существующей БД. Для пустой установки нужен обычный setup/запуск.

Из канонического каталога проекта:

```powershell
.\scripts\start-orion-clinic.ps1 -SkipDataInitialization
```

По необходимости можно явно добавить `-Device Cpu` или `-Device Cuda`;
по умолчанию остаётся `Auto`. Не меняйте устройство для маскировки ошибки запуска.

В этом режиме:

- `db:migrate:local` и `db:bootstrap:local` не вызываются; основной D1/R2,
  существующие записи и аудио не мигрируются и не очищаются launcher'ом.
- Предыдущие логи сохраняются. Новый запуск получает отдельный каталог
  `.orion-runtime/logs/recovery-<дата-время>-<случайный-id>/` и выводит его путь.
- Уже готовый сервис используется повторно; занятый порт не освобождается силой.
  Launcher не удаляет существующий Vinext lock: установленный Vinext сам проверяет
  его при запуске и не перехватывает работающий процесс. Защита портов сохраняется.
- Сервисы запускаются скрыто и только на прежних loopback-портах 3200/3101.
  Это не внешняя публикация, не включение индивидуальных аккаунтов и не production.
- При ошибке не повторяйте обычный запуск автоматически: он применяет все pending
  migrations и bootstrap. Сначала прочитайте выведенный путь к новому error log.

Без `-SkipDataInitialization` поведение намеренно прежнее: нуждающийся в запуске
контур применяет миграции и bootstrap, затем использует стандартные имена логов.
Пока новый auth/material-контур не допущен к основной БД, используйте именно
явный режим восстановления, чтобы не применить отложенные миграции 0048–0051.

После запуска проверьте `/api/health/ready` на 3200 и `/health` на 3101. Затем
отдельно проверьте браузерную навигацию и, если это входит в текущую задачу,
распознавание искусственного аудио. HTTP 200 не доказывает качество речи, доступность
Groq, сохранность записи после сбоя или готовность всех пользовательских сценариев.

Никакие секреты, тексты консультаций или аудио не копируйте из логов в отчёт.
Не удаляйте основную БД, R2, историю браузера, аудио или кэши для «починки запуска».
