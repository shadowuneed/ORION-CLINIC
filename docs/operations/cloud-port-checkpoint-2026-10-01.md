контур и отделяет аналитику кнопкой. Это не полная история изменений и не
счётчик задач всей клиники. В живом браузере показана уже существующая

Срочные клинические задачи, анализы, наблюдение и коммуникации не подменяются
придуманными событиями: экран прямо показывает неподключённые источники.

## Подготовлено, но не включено онлайн

Подготовленный код сохранён и отправлен в существующую облачную ветку коммитом
`5b38d28b3cb26ac148bd7dc668fe2bd80aa0c662`. Это не опубликованный a4df3b2;
последующее обновление документов не требует нового деплоя.

`cloud/sql/0005_patient_observations.sql` создаёт четыре закрытые таблицы с RLS
и пять узких API-функций. SHA256 проверенного исходника:
`AD22ADB4B510255881B56DD273BE14CDAC646E5058995AE5076864533BF7D0C1`.
Это новая отдельная миграция, не повтор0001–0004 и не изменение локальной базы.
Подтверждение её применения запрошено у владельца; на этой контрольной точке
подтверждения и исполнения в Supabase нет.

Подготовлены:

- выбранный пациент и точное назначение врача/медсестры с `observations.manage`;
- реальные сохранение и исправление с причиной, проверкой текущей версии,
  неизменяемой историей, атомарным аудитом и точным повтором без дубликатов;
- отдельные последние значения роста/веса/ИМТ, давления и температуры с их
  собственным временем, автором и источником;
- ограниченный список по25, отдельная постраничная история, безопасный отказ
  при смене прав, пациента, позиции страницы или поколения сеанса;
- интерфейс ввода и исправления: только искусственные данные, незаполненные
  группы не превращаются в нормальные значения, неизвестный результат сохраняет
  точные тело и ключ команды для повтора;
- карточка пациента с проверкой полного облачного ответа и переходом
  `/observations` с сохранением пациента, филиала и назначения;
- схема женщины/мужчины по явно записанному полу, без вывода пола по имени,
  без выдуманных диагнозов, тревог или оценки риска.

API и страница показателей пока не пропускаются облачным ingress, а карточка
получает `vitalsAvailable={false}`. Ни новый флаг окружения, ни готовый файл
миграции не снимают этот запрет. Не публиковать функцию как работающую до
применения и проверки каталога БД и живого сценария.

## Свежая проверка подготовленных исходников

Команды из `ORION-CLINIC-CLOUD`:

```powershell
pnpm.cmd test lib/cloud cloud app/sign-in app/dashboard app/patients app/observations lib/workspace-access-url.test.ts
pnpm.cmd exec tsc --noEmit
pnpm.cmd security:secrets
git diff --check
```

Основной сфокусированный прогон:816 тестов в37 файлах PASS,98.82секунды;
TypeScript PASS, сканер804 файлов PASS, diff-check PASS. После него окончательный
повтор77 тестов в четырёх файлах PASS,5.42секунды:

```powershell
pnpm.cmd exec vitest run app/patients/patient-cloud-vitals.test.ts app/patients/patient-pagination-ui.test.ts lib/cloud/observation-client-fence.test.ts app/observations/cloud-observations.test.ts --maxWorkers=1
pnpm.cmd exec tsc --noEmit --pretty false --incremental false
```

Окончательный TypeScript, ESLint изменённых исходников и сканер805 файлов PASS.
Отложенные ответы проверяются настоящими `Response`/`ReadableStream`, а не
подменой метода JSON. Эти77 тестов пересекаются с основным прогоном; складывать
их в общий счётчик нельзя. По просьбе владельца закруглиться новая разработка,
миграция и публикация остановлены; сохраняется только подготовленная точка.

SQL проверялся в локальном тестовом PostgreSQL/PGlite, включая реальный путь
через экспортированные HTTP API и transport. Эти результаты не означают
применение0005 в удалённом Supabase, живой отзыв провайдера, работу двух
человеческих аккаунтов, полную `verify:ci` или клинический допуск.
