## Что исправлено

1. Разрешены только GET/HEAD запросы к статическим Next-файлам динамических
   маршрутов с `[patientId]`. Их блокировка вызывала ChunkLoadError при открытии
   сохранённой карточки. Кодировки разделителей и обходы путей не разрешались.
2. Сохранены проверенные серверные коды конфликта версии и обычного отказа
   изменения. Устаревшая вкладка теперь предлагает загрузить актуальную карточку;
   известные отказы больше не превращаются в ошибку недоступности сервера.
   Непроверенные сообщения Supabase не возвращаются клиенту.
3. Главный адрес направляет в рабочий реестр, сохраняя только явные селекторы
   назначения и клиники. Меню показывает облачные разделы, которые уже подключены,
   без ссылок на неперенесённые клинические инструменты. Полномочия не расширены.

В первом промежуточном деплое относительный redirect вызвал 500 на `/`.
Он исправлен абсолютным same-origin URL и повторно опубликован. Проверяется
именно итоговая версия выше, не промежуточная сборка.

## Что ещё не доказано и куда продолжать

Основной CRUD-сценарий не заменяет живую проверку повторного запроса с одним
idempotency key и изменённым телом, изоляции двух аккаунтов или отзыва сеанса
через провайдера. Эти проверки остаются открытыми. Новые аккаунты и назначения
не создавать без участия владельца; пароли он вводит сам.

После этих проверок отдельно переносить показатели и уведомительный центр:
нужны узкие серверные API и одобренная forward-миграция, а не открытие старых
маршрутов флагом. Итоги dashboard нельзя вычислять по первой странице 25 карт.
Показатели берутся из сохранённых измерений; риск-проценты, диагнозы и тревожные
события не рисуются. Пороговые клинические правила пока не утверждены.
Приёмы, маршрут, назначения, наблюдение, расписание, коммуникации и хранилище
ещё не перенесены. Облачный STT остаётся отложенным.

Блокировка не обходилась альтернативным launcher или shell.

В обычном PowerShell владелец может запустить существующий web-only wrapper:

```powershell
Set-Location -LiteralPath 'C:\Users\profm\OneDrive\Документы\ChatGPT\ORION-CLINIC'
. .\scripts\resolve-local-runtime.ps1
$orionRuntime = Resolve-OrionLocalRuntime
.\scripts\run-orion-web.ps1 -ProjectRoot (Get-Location).Path -PnpmPath $orionRuntime.Pnpm -NodeBin $orionRuntime.NodeBin
```

Wrapper использует `vinext dev --hostname 127.0.0.1 --port 3200`, не выполняет
миграции, bootstrap или seed. После запуска вход: http://127.0.0.1:3200/sign-in .
Общие launchers, которые могут применять миграции, для этого показа не нужны.
